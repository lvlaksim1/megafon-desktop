# Действующие правила проекта MegaFon Desktop

- Продукт — отдельный настольный клиент для частных (B2C) аккаунтов MegaFon, не B2B-клиент; подтверждённая архитектура и полномочия менеджера определены в `.context/manager/mandate.md`.
- Обновление данных допускается только по явному действию пользователя. Не выполнять скрытое обновление при запуске.
- Действия на реальных аккаунтах, способные изменить услуги, тариф, предложения или расходы, требуют предусмотренного согласования владельца и проверки текущего сетевого договора. Не выдавать неподтверждённые протоколы за действующие.
- Возобновление и смену токена выполнять только по доказанному источнику, без выдумывания адресов и опытов с истечением срока.
- Пароли, сеансы, куки, токены и иные персональные данные не публиковать; сохранять предусмотренную защиту учётных записей.
- Приоритет текущего проверенного направления — Qt Widgets/QTableWidget и пользовательская приёмка опубликованной v0.3.6. Ранее отклонённый вариант QML не восстанавливать без решения владельца.
- Статус сборки, выпуска и реальной приёмки различать. Подтверждение публикации не подменяет пользовательскую проверку.

Основание: `.context/manager/mandate.md`, `.context/manager/beliefs.md`, `.context/current/state.md`, `.context/current/next.md`. Эти правила систематизируют уже зафиксированные указания; новых полномочий не предоставляют.

## Основная рабочая среда (OWNER-LOCAL-FIRST-2026-10-30)

Основная разработка и хранение капсулы выполняются на DOMKAT, в каталоге D:\Dev. GitHub используется для истории версий, синхронизации и резервного восстановления, но прямая разработка в GitHub допускается как исключение. Сохранять полномочия веток продукта и менеджера, проверять целостность капсулы, расхождения Git и неопубликованные локальные изменения. Подробности в файле .context/rules/local-first-workspace.md.

## Стандарт пакетной разработки (OWNER-BATCH-EXECUTION-2026-10-30)

Выполнять разработку по правилу Владельца 30.10.2026: одна стадия планирования моделью, один исполняемый пакет операций на DOMKAT, один содержательный итоговый отчёт. GUI-операции примерно через одну секунду; PowerShell/CMD/Git/файлы без искусственных пауз. Неожиданная ошибка возвращается модели для оценки; остановка всей работы или обращение к Владельцу производится только по обоснованной необходимости. Подробный норматив: .context/rules/batch-development-standard.md. Правило не изменяет полномочия менеджера и существующие ограничения.
